## Research Notes Guide

Use this folder to record every useful source, extraction test, and reference check that may affect the prototype.

### File Naming
Use one note per source or test run.

Recommended formats:
- `YYYY-MM-DD-topic.md`
- `YYYY-MM-DD-source-name.md`
- `YYYY-MM-DD-extraction-test.md`

Examples:
- `2026-04-03-divekick-unity3d.md`
- `2026-04-03-satrgb-texture-test.md`
- `2026-04-03-fighting-vipers-sound-reference.md`

### Status Values
Use one of the following:
- `todo`
- `testing`
- `usable`
- `blocked`
- `rejected`

### What Should Go Here
- External project references
- Emulator findings
- Move timing notes
- Model, texture, and audio extraction tests
- Tool setup issues
- Reusable conclusions for Unity implementation

### What Should Not Go Here
- Final design docs
- General task planning with no research result
- Large binary outputs
- Raw screenshots or captures without context

### Related Folders
- Captures: `../Captures/`
- Move lists: `../MoveLists/`
- Original assets: `../OriginalAssets/`
- Extraction tools: `../../Tools/Extraction/`

### Recommended Workflow
1. Copy `_template.md` to a new dated note.
2. Fill in source, goal, and status first.
3. Add evidence paths as you collect files.
4. End with a decision and next action.
5. Keep one topic per note so results stay searchable.
