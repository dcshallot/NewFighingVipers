# Honey 资产技术规格

状态：C1/C2 前置规格；性能预算在 Unity 验证后允许通过决策记录调整。

## 坐标与尺度

- Blender 使用公制单位，角色直立于地面原点；
- 角色面向统一前向，导出前不得保留非单位缩放；
- Unity 中 `1 unit = 1 meter`；
- pivot、根骨、角色高度和前向必须写入 C2 评审记录；
- 镜像修改器、负缩放和未应用 transform 不得进入批准导出。

## 文件与命名

- 工作源文件：`Honey_<Stage>_vNNN.blend`；
- 批准主文件：`Honey_Master.blend`；
- Unity 稳定导出：`Honey.fbx`，不在文件名中滚动版本；
- mesh：`CHR_Honey_<Part>`；
- armature：`RIG_Honey`；
- material：`M_Honey_<Region>`；
- texture：`T_Honey_<Region>_<Map>`；
- 禁止空格、个人缩写和没有意义的 `final_final`。

## 几何

初始 LOD0 预算：

- 完整角色不超过 100,000 triangles；
- 单独透明层、毛发卡和装饰必须纳入总预算；
- 材质槽目标不超过 6；
- skinned mesh renderer 目标不超过 8；
- 单顶点有效骨骼影响不超过 4。

这些是上限而非目标。C6 以双角色和竞技场性能验证决定是否收紧。

质量要求：

- 无非预期非流形、重复顶点、内部悬空面和翻转法线；
- 肩、肘、腕、髋、膝、踝具有可变形边流；
- 脸和关键轮廓保留足够密度；
- 双马尾、裙摆和袖口采用明确的独立控制结构；
- 仅为雕刻存在的高模不得直接作为游戏导出。

## UV 与纹理

- UV0 用于材质；需要时 UV1 用于烘焙或游戏用途；
- 非设计性重叠禁止；对称复用必须记录；
- 同一材质区域保持一致 texel density；
- 单张纹理上限 4096×4096；评审和原型优先 2048；
- 使用 Unity URP 可解释的 Base Color、Normal、Mask 等组合；
- 不将原作 dump 或 AI atlas 原样当成最终可发布贴图；
- 工作色彩空间和法线格式必须在导出说明中记录。

## 材质

- 避免为微小部件创建独立材质槽；
- 透明材质仅在无法用 cutout/geometry 解决时使用；
- 皮肤、头发、布料、皮革／靴子、金属装饰需有可区分但统一的响应；
- Blender 与 Unity URP 的差异必须在固定中性灯光下比较。

## 骨架与蒙皮

- 根骨、骨盆、脊柱、四肢和头部命名及层级保持稳定；
- 目标为 Unity Humanoid 兼容，但不以 Avatar 全绿替代变形验收；
- 双马尾、裙摆、袖口可使用附加骨骼，必须有确定层级和约束；
- 总骨骼初始上限 120；
- 不允许遗留未使用 deform bones 或非预期约束；
- idle、walk、hit、kick 是 C5 最小变形集。

## 导出

- 导出只来自批准主文件和批准 collection；
- 应用规定的轴向、单位和 transform；
- 不导出相机、灯光、参考平面、高模和隐藏试验件；
- 导出前记录源文件 SHA-256、Blender 版本和导出参数；
- 导出后记录 FBX SHA-256，并在干净 Unity 验证场景复验；
- 固定文件名由 Git/LFS 历史管理版本。

## Unity 验证

- 工程位于 `Game/`，Unity 6 + URP；
- 必须提交 `.meta`、Prefab、材质、Animator 和验证场景；
- 检查尺度、朝向、骨架映射、材质、法线、阴影和 clip；
- 固定视角截图和动作结果进入 Review；
- C6 前只建立资产验证功能，不扩展完整战斗系统。

## 阻塞级问题

- 来源不清的内容进入最终纹理或网格；
- 无法稳定重复导出；
- 骨架层级或命名在导出间变化；
- 主要关节塌陷或裙摆、头发产生大面积穿模；
- 固定视角下关键轮廓明显偏离已冻结 Character Bible；
- Unity 中出现无法解释的比例、法线或材质差异；
- 超预算且没有性能证据支持。
