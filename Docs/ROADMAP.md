# 制作路线图

## 范围

当前只推进方向 C 的 Honey 正常状态。破甲状态、其他角色、完整战斗系统和发布内容均不在当前阶段。

## C0：基线就绪

交付物：

- 当前状态、决策、路线图和 Honey 验收文档；
- 参考与资产 manifest；
- Git、LFS、`LocalData/` 和备份边界；
- 工具状态清单与平台说明；
- Mac-first 环境说明和只读健康检查。

通过条件：

- 文档入口和相对链接有效；
- 所有现有工具均进入清单；
- 受限资料不能被普通 Git 或 LFS 意外跟踪；
- Mac M4 能运行环境检查；
- 缺少 Windows/CUDA 能力只报告为可选，不阻塞方向 C；
- C1 所需模板可直接填写。

## C1：参考冻结

交付物：

- 已填写的 `honey-reference-manifest.csv`；
- Honey 正、侧、背和游戏镜头关键参考；
- 完整的角色比例、轮廓、分件、颜色和材质说明；
- 争议项和允许补充设计的边界。

通过条件：

- 每项采用参考均有来源、逻辑路径、SHA-256、用途和权利状态；
- 正侧背比例可相互解释；
- 双马尾、裙摆、袖口、靴子、手套和装饰关系明确；
- 没有会迫使 C2 反复推翻主体比例的阻塞歧义。

## C2：Blockout

交付物：

- 可编辑 Blender 主文件；
- 固定正、侧、背、四分之三和游戏镜头评审图；
- 初步身体、服装和头发分件方案。

通过条件：

- 固定视角轮廓和身体比例通过；
- 游戏镜头下角色可读；
- 独立控制部件方案可执行；
- 未通过不得进入细节雕刻。

## C3：拓扑和 UV

交付物：

- 变形友好的游戏拓扑；
- UV 布局和材质槽；
- 双马尾、裙摆、袖口的控制设计；
- 拓扑和 UV 检查报告。

通过条件：

- 肩、肘、腕、髋、膝、踝和面部关键区域边流合理；
- 无非预期非流形、重叠面或负缩放；
- UV 无非预期重叠，texel density 满足规格；
- 关键轮廓未因减面明显损失。

## C4：材质

交付物：

- 可编辑材质源文件；
- Base Color、Normal、Mask 等 Unity 所需纹理；
- 固定中性光照和游戏光照评审图。

通过条件：

- 颜色与采用参考一致；
- 脸、头发、裙边、蕾丝和金属件无明显脏边；
- AI 生成内容已经转为可编辑、来源明确的底稿，不存在不可追溯依赖；
- Unity URP 显示与 Blender 评审无阻塞差异。

## C5：绑定和变形

交付物：

- 稳定骨架、蒙皮和辅助骨骼；
- idle、walk、hit、kick 四组固定测试姿势或 clip；
- 变形问题清单和修复结论。

通过条件：

- 标准人形关节无阻塞级塌陷；
- 双马尾、裙摆和袖口在测试动作下可控；
- 无大面积穿模、权重跳变或骨架尺度问题；
- 重复导出不会改变骨骼命名、层级和朝向。

## C6：游戏就绪验收

交付物：

- 经批准的源模型、材质和固定名称导出；
- Unity URP 固定验证场景；
- 正侧背、游戏镜头、动作和性能报告；
- 完整资产 manifest 与里程碑 Git/LFS 版本；
- 干净工作区导出／导入复现记录。

通过条件：

- `QA_CHECKLIST.md` 无阻塞项；
- 来源、版本、哈希和导出闭环；
- 单角色场景保留扩展到双角色和竞技场的性能余量；
- 无受限或来源不明素材进入发布资产。

## 方向 C 到方向 B 的 Gate

必须同时满足：

- Honey 正常状态拥有可维护的源模型、稳定拓扑、UV、材质、骨架和权重；
- 固定动作测试不存在阻塞级变形问题；
- 固定正侧背和游戏镜头评审通过；
- 干净工作区能够重复完成导出和导入；
- 正式资产不依赖来源不清或不可发布的外部素材；
- 源文件、批准导出、manifest、哈希与 Git/LFS 里程碑闭环；
- 单角色性能具有双角色扩展余量；
- 所有阻塞项关闭，非阻塞项有 owner 和后续阶段；
- Windows 目标平台验证方案已准备。

Gate 未通过时，只允许在 `Game/` 内维护角色导入、固定镜头、动作和性能验证，不扩展战斗功能。

## 方向 B 首个范围

Gate 通过后另行立项，首个 vertical slice 只包含：

- Honey 与一个占位对手；
- 1 个测试竞技场；
- 移动、站立、拳、脚、防御、受击、击退和 hit stop；
- 本地输入和基础训练验证；
- macOS 日常开发及 Windows 里程碑验证。
